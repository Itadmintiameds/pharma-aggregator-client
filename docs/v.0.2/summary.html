01

Architecture

Every client request enters through one gateway. Discovery and Config sit alongside it as the platform layer. Domain services talk to each other directly (sync, solid line) only where a caller needs an answer inside its own request; everything else moves over the event backbone (async, dashed).

Full per-edge rationale: ADR-003 (sync/async default), ADR-004 (Billing), ADR-005 (Search), ADR-009 (event backbone).

03

Sync vs. async, in one rule

A call is synchronous only when the caller cannot return a correct response without the result in the same request. Everything else runs over the event backbone.

Sync Direct, in-request

via Cloud Map resolution, bypasses the gateway
  • Order → Product — stock/price check before confirming a line item.
  • Quotation → Order — creates the order the instant a quote is accepted.
  • Billing → Order — line-item detail fetched at invoice-render time, never persisted.

Async Event-driven

EventBridge + SQS per consumer; MSK only where flagged
  • Order → Billing, Notification — OrderConfirmed fan-out.
  • Product → Search — ProductChanged rebuilds the index; Kafka candidate (ADR-009).
  • Quotation, Billing → Notification — delivery log, no synchronous caller ever waits on it.
04

Region topology

One Terraform module per service, region passed as a variable — adding a region is a scripted action, not manual per-service setup (ADR-006). Write topology splits by data sensitivity, not by service tier:

ModeServicesWhy
Single-writer + warm standbyOrder, Billing, Seller User, Buyer User, QuotationAurora PostgreSQL Global Database — one writer region at a time; transactional correctness over instant failover.
Active-activeProduct Management, Search (OpenSearch), Master/Reference DataRead-heavy, lag-tolerant — DynamoDB Global Tables and independent index replicas per region.
05

Decisions, condensed

Nine ADRs govern this topology; full context, alternatives, and trade-offs live in the ADR doc.

ADR-001
11 services, not 5 — finer split for independent scaling; master data stays a shared module.
ADR-002
Discovery/Config go AWS-native (Cloud Map, AppConfig) over self-hosted Eureka/Consul.
ADR-003
Async by default; sync only where the caller needs the answer this request.
ADR-004
Billing stores order_id only, never copies Order's data.
ADR-005
Search owns an index, not source data — rebuilt from Product events.
ADR-006
One Terraform module per service, region as a variable — one-click multi-region.
ADR-007
Single-writer for transactional services, active-active for read-heavy ones.
ADR-008
API Gateway is the only client-facing entry point; service-to-service calls bypass it.
ADR-009
EventBridge by default; Kafka (MSK) only for edges needing ordered replay or multiple consumer groups.
